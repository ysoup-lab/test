预编译的好处

预编译（PreparedStatement）的好处主要可以从 安全性、性能、类型安全、可维护性 四个角度来理解：

1. 防止 SQL 注入（安全性）

  • SQL 语句和参数分离，用户输入只作为“值”绑定到 ? 占位符上。
  • 数据库不会把参数解析为 SQL 代码，避免恶意输入改变 SQL 逻辑。
  • 示例：
String sql = "SELECT * FROM user WHERE id = ?";
pstmt.setInt(1, userInput); // 安全绑定

2. 提升性能（尤其是服务端预编译 + 缓存）

  • 客户端预编译：驱动在本地把参数拼接成完整 SQL，减少了 Java 层的拼接开销。
  • 服务端预编译：
    1. SQL 模板只解析一次，生成执行计划。
    2. 后续执行相同模板，只需绑定参数即可。
    3. 减少数据库解析、优化和 round-trip 网络开销。
  • 对于高频查询和批量操作，性能提升显著。

3. 类型安全 / 自动转换

  • JDBC 驱动帮你把 Java 类型（int, String, Date）转换为对应的数据库类型。
  • 避免手动拼接时引号、日期格式、转义字符等错误。
  • 类型不匹配会直接报错，而不是被解析成 SQL，增加安全性。

4. 提高代码可维护性

  • SQL 模板和参数分离，更清晰、可读性高。
  • 便于重用、批量操作和动态参数处理。
  • 示例：
String sql = "INSERT INTO t(a,b) VALUES (?, ?)";
pstmt.setInt(1, a);
pstmt.setString(2, b);
pstmt.addBatch();

5. 总结表

好处描述
安全性防止 SQL 注入，数据和代码隔离
性能减少数据库解析、优化开销；服务端预编译 + 缓存可复用执行计划
类型安全JDBC 自动类型转换，类型不匹配直接报错
可维护性SQL 模板和参数分离，支持批量操作，代码更清晰

可以说，预编译是 JDBC 提供的核心机制，既保证安全，又有可能提高性能，是企业级数据库操作的标准做法。

如何预防sql注入攻击的

这个问题本质就是：PreparedStatement 为什么比 Statement 安全。

1. Statement 的做法（不安全）

String sql = "SELECT * FROM user WHERE id = " + userInput;
Statement stmt = conn.createStatement();
ResultSet rs = stmt.executeQuery(sql);

如果用户输入 1 OR 1=1，最终拼出来的是：

SELECT * FROM user WHERE id = 1 OR 1=1;

这条 SQL 语义被改变了，导致全表扫描返回所有用户 —— 典型 SQL 注入。

2. PreparedStatement 的做法（安全）

String sql = "SELECT * FROM user WHERE id = ?";
PreparedStatement pstmt = conn.prepareStatement(sql);
pstmt.setInt(1, userInput);

执行流程：

  1. 预编译阶段
    • 数据库先解析 SQL 模板 SELECT * FROM user WHERE id = ?，生成执行计划，? 是一个“占位符”。
  2. 绑定参数阶段
    • JDBC 驱动通过二进制协议（或类型化 API）把参数作为“值”传给数据库（比如 1 是 int 类型，"abc" 是 varchar 类型）。
    • 参数不会被当成 SQL 语法解析。
  3. 执行阶段
    • 数据库直接用绑定的值代入执行计划，不会重新解析 SQL 字符串。

3. 为什么能防止注入

  • 值和代码分离：SQL 模板是固定的，用户输入只能作为值出现，永远不会影响 SQL 的结构。
  • 类型检查：驱动会按 setInt / setString 等方法，把参数按类型传输，数据库侧也会校验参数类型（int、varchar 等）。如果类型不符，直接报错，而不是执行成另一段 SQL。
  • 自动转义（当客户端需要模拟拼接时）：驱动会对特殊字符（如 '）进行转义，保证它们只是数据的一部分，而不是语法。

4. 举个例子

用户输入：

"1 OR 1=1"

  • 用 Statement 拼接 →

    SELECT * FROM user WHERE id = 1 OR 1=1;

    成功注入。

  • 用 PreparedStatement →

    SELECT * FROM user WHERE id = '1 OR 1=1';

    这里 '1 OR 1=1' 是一个字符串字面量，数据库会去查找 id = '1 OR 1=1' 的行（结果为空），而不是解析成 SQL 逻辑。

✅ 总结一句：
PreparedStatement 通过 SQL 预编译 + 参数类型化绑定 的机制，把 数据和代码隔离，从根本上防止 SQL 注入。

mybatis的调用方式

整理三种 MyBatis 调用 SQL 的方式，每种都配上完整的示例代码（不考虑 Spring，只用原生 MyBatis）：

1. 直接通过 SqlSession 调用（最原始方式）

完全不需要接口，也不需要 XML，只要有 Mapper 配置文件就能用。

import org.apache.ibatis.io.Resources;
import org.apache.ibatis.session.SqlSession;
import org.apache.ibatis.session.SqlSessionFactory;
import org.apache.ibatis.session.SqlSessionFactoryBuilder;

import java.io.InputStream;

public class MyBatisDemo1 {
    public static void main(String[] args) throws Exception {
        // 1. 读取配置文件
        InputStream inputStream = Resources.getResourceAsStream("mybatis-config.xml");
        SqlSessionFactory sqlSessionFactory = new SqlSessionFactoryBuilder().build(inputStream);

        // 2. 获取 SqlSession
        try (SqlSession sqlSession = sqlSessionFactory.openSession()) {
            // 3. 直接通过 namespace.id 调用
            User user = sqlSession.selectOne("com.example.UserMapper.selectById", 1);
            System.out.println(user);
        }
    }
}

对应的 UserMapper.xml：

<mapper namespace="com.example.UserMapper">
    <select id="selectById" parameterType="int" resultType="User">
        SELECT * FROM user WHERE id = #{id}
    </select>
</mapper>

2. 接口 + XML 映射（常用方式）

Mapper 接口没有实现类，MyBatis 会用 JDK 动态代理生成。

// UserMapper.java
public interface UserMapper {
    User selectById(Integer id);
}
// MyBatisDemo2.java
public class MyBatisDemo2 {
    public static void main(String[] args) throws Exception {
        InputStream inputStream = Resources.getResourceAsStream("mybatis-config.xml");
        SqlSessionFactory sqlSessionFactory = new SqlSessionFactoryBuilder().build(inputStream);

        try (SqlSession sqlSession = sqlSessionFactory.openSession()) {
            // 获取 Mapper 接口的代理对象
            UserMapper mapper = sqlSession.getMapper(UserMapper.class);
            User user = mapper.selectById(1);
            System.out.println(user);
        }
    }
}

对应的 UserMapper.xml：

<mapper namespace="com.example.UserMapper">
    <select id="selectById" parameterType="int" resultType="User">
        SELECT * FROM user WHERE id = #{id}
    </select>
</mapper>

3. 接口 + 注解方式（不需要 XML）

适合 SQL 比较简单的场景，直接写在接口上。

import org.apache.ibatis.annotations.Select;

public interface UserMapper {
    @Select("SELECT * FROM user WHERE id = #{id}")
    User selectById(Integer id);
}
// MyBatisDemo3.java
public class MyBatisDemo3 {
    public static void main(String[] args) throws Exception {
        InputStream inputStream = Resources.getResourceAsStream("mybatis-config.xml");
        SqlSessionFactory sqlSessionFactory = new SqlSessionFactoryBuilder().build(inputStream);

        try (SqlSession sqlSession = sqlSessionFactory.openSession()) {
            UserMapper mapper = sqlSession.getMapper(UserMapper.class);
            User user = mapper.selectById(1);
            System.out.println(user);
        }
    }
}

注意：要在 mybatis-config.xml 里配置 <mappers>，指定 UserMapper 接口所在的包，MyBatis 才能识别注解方式。

📌 总结对比

调用方式是否需要接口是否需要 XML适用场景
直接 SqlSession 调用否是快速测试，灵活，但不适合大项目
接口 + XML是是最常用，适合复杂 SQL，团队开发标准做法
接口 + 注解是否SQL 简单、快速开发

从调用方式思考，如果要实现 MyBatis 第二种调用方式，底层是怎么实现的？我们需要先了解没有 mybatis，jdbc是如何实现和mysql的交互的？

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;

public class JdbcDemo {
    public static void main(String[] args) {
        // 数据库连接信息
        String url = "jdbc:mysql://localhost:3306/test?useSSL=false&serverTimezone=UTC";
        String user = "root";
        String password = "123456";

        // JDBC 对象
        Connection conn = null;
        PreparedStatement pstmt = null;
        ResultSet rs = null;

        try {
            // 1. 加载驱动（JDBC 4.0 之后可以省略）
            Class.forName("com.mysql.cj.jdbc.Driver");

            // 2. 获取连接
            conn = DriverManager.getConnection(url, user, password);

            // 3. 预编译 SQL
            String sql = "SELECT id, name FROM user WHERE id > ?";
            pstmt = conn.prepareStatement(sql);
            pstmt.setInt(1, 0); // 参数赋值

            // 4. 执行查询
            rs = pstmt.executeQuery();

            // 5. 遍历结果集
            while (rs.next()) {
                int id = rs.getInt("id");
                String name = rs.getString("name");
                System.out.println(id + " - " + name);
            }
        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            // 6. 关闭资源（注意顺序：结果集 → 语句 → 连接）
            try {
                if (rs != null) rs.close();
                if (pstmt != null) pstmt.close();
                if (conn != null) conn.close();
            } catch (Exception e) {
                e.printStackTrace();
            }
        }
    }
}

这个例子就是最基础的 JDBC 调用流程：

  1. 加载驱动
  2. 建立连接
  3. 预编译 SQL
  4. 执行 SQL
  5. 遍历结果集
  6. 关闭资源
public class MyBatisDemo3 {
    public static void main(String[] args) throws Exception {
        InputStream inputStream = Resources.getResourceAsStream("mybatis-config.xml");
        SqlSessionFactory sqlSessionFactory = new SqlSessionFactoryBuilder().build(inputStream);
        // 第一第二步骤应该在 sqlSession 中完成
        try (SqlSession sqlSession = sqlSessionFactory.openSession()) {
            UserMapper mapper = sqlSession.getMapper(UserMapper.class);
            User user = mapper.selectById(1);
            System.out.println(user);
        }
    }
}

从 UserMapper mapper = sqlSession.getMapper(UserMapper.class); 这个步骤做完后下一步就传入参数然后调用，我们可以猜测 这一步应该是完成了创建Statement对象，获取对应配置的sql，然后完成预编译。
而要实现从对应的接口调用能走到这一步肯定是通过代理对象，代理对象的创建应该时调用sqlSession.getMapper这一个步骤

String sql = "SELECT id, name FROM user WHERE id > ?";
pstmt = conn.prepareStatement(sql);
